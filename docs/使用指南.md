# 使用指南

dots-lite 让你在微信中通过自己的 Hermes，操作自己电脑上已授权文件夹中的工作。你用自然语言说明任务和工作目录，Hermes 负责跟进执行、检查结果和取回文件。普通文件夹也可以，不要求先建 Git 项目。

文中使用授权文件夹编号 `projects` 和示例根 `C:\workspaces`。实际范围由你在部署时指定，不是程序内置目录。真实微信审批、附件收发与多台执行电脑需按各部署环境验收；本文示例不表示这些权限已授予。

管理员接入步骤见[运行指南](运行指南.md)，已验证范围见[验收记录](验收记录.md)。

## 第一次使用前

请管理员确认以下条件：

1. 你的微信账号和聊天已绑定到自己的 Hermes profile。
2. 自己电脑上的执行端已启动，并连接到服务器的 Hub。
3. 要操作的工作目录位于授权文件夹内且真实存在，Codex 在该电脑上可用。
4. 该 profile 的来源插件、MCP 和后台 worker 均已接好。

你不需要在微信中提供 SSH 密钥、执行端 token 或 API token。任务通过执行端主动建立的 WebSocket 连接传输，不依赖服务器 SSH 登录你的电脑。维护 SSH 与任务连接相互独立，不需要向服务器提供登录执行电脑的 SSH 权限。

先向自己的 Hermes 发送：

> 查看我绑定的执行电脑是否在线、Codex 是否初始化成功，并列出我能使用的授权文件夹。只查询，先不要创建任务。

电脑连接、Codex 初始化和文件夹可用是三项不同的检查。只看到“电脑在线”还不能说明可以开始任务。

## 完成第一个任务

先查询授权文件夹。下面使用本机的 `projects`。不指定子目录时，任务就在授权根目录工作：

> 在授权文件夹 projects 本身新建任务，名称是“接入检查”。创建 notes/duet-check.txt，内容为 hello duet。把这个文件登记为交付产物。完成后读取实际文件核对内容，再取回并发到当前聊天。请先告诉我任务编号。

这条示例会在项目中创建一个文件，并要求向当前聊天交付。只在你同意这些动作时使用。

Hermes 应返回稳定的任务编号，例如 `task_…`。保存完整编号。后续查看、继续和停止都用这个编号，不用“刚才那个任务”定位多个并行工作。

若已有 `C:\workspaces\demo`，可直接说“在 projects 下的 demo 文件夹里完成……”。Hermes 使用 `folder_id=projects` 和相对 `working_directory=demo`，无需让管理员再登记 demo。工作目录须已存在；新目录可以在授权根目录的任务中按你的要求创建，服务不会暗中创建缺失的工作目录。

任务创建后，工作目录保持不变。继续、追加、读取、上传和产物路径都相对这个任务目录；更换目录要新建任务。

等待任务结束后，分别确认三个结果：Codex 完成了执行，Hermes 检查了实际内容，你在聊天中收到了文件。只有文字声称“完成”或只给出电脑上的路径，都不证明文件已送达。

## 日常操作

下列消息都是自然语言示例，不是程序内置的斜杠命令。把 `task_…` 换成实际任务编号。

| 目的 | 可以发给 Hermes 的消息 |
| --- | --- |
| 列出任务 | “列出我的任务，显示编号、授权文件夹、工作目录、执行状态、待处理问题、核验和交付状态。” |
| 浏览工作目录 | “列出授权文件夹 projects 下的目录，先不要创建任务。” |
| 查看一个任务 | “查看 task_… 的当前状态，告诉我实际做到哪里，还有什么没确认。” |
| 查看历史 | “读取 task_… 的会话历史，概括最近的要求和结果。” |
| 继续原任务 | “继续 task_… 的同一会话：补充一段使用说明，并核对实际文件。” |
| 执行中追加要求 | “给正在执行的 task_… 追加要求：不要修改现有接口。先确认它仍是当前运行回合。” |
| 停止任务 | “停止 task_…，暂停它的持续目标，并核对实际执行是否已经停止。” |
| 查询停止结果 | “查看 task_… 的暂停记录和原生执行状态，确认是否真的停止。” |
| 查看目录 | “列出 task_… 工作目录中的 output 目录。” |
| 阅读文本 | “读取 task_… 的 output/report.md，说明是否有截断。” |
| 补取文件 | “从 task_… 下载 output/report.md，核对大小和哈希，告诉我是否完整取得。” |
| 查看交付 | “查询 task_… 的产物和交付回执，区分文件已取回、已发送和结果未知。” |

“继续”用于在原会话开始下一回合；“追加”用于引导当前仍在执行的回合。若当前回合已经结束，Hermes 应重新查询状态，再按你的意图继续，不能把旧回合编号套到新回合。

同一工作目录或相互包含的目录存在冲突写任务、活动 Goal 或未确认的操作时，另一个任务可能需要等待。不同兄弟目录可分别执行；同一授权文件夹出现未知写结果时仍保守等待核对。停止或交接前要核对原生执行和 Goal。关闭微信窗口不会停止电脑上的任务。

## 使用附件与取得结果

新任务可引用本条已授权微信消息携带的附件。例如附上一份 `data.csv`，同时发送：

> 在 projects 下已有的 demo 文件夹里新建任务“数据检查”。使用本条消息附带的 data.csv，统计记录数和各列缺失值，生成 output/check.md。把报告登记为交付产物，核对后发回当前聊天。

如果客户端不能给文件附上任务文字，可以先说明：“下一条文件到达时，请在 projects 下的 demo 文件夹中开始数据检查，并按刚才的要求处理。”然后发送文件，让 Hermes 在处理该文件消息时引用附件。不能先发文件，再在另一条消息中用旧路径授权读取。这个真实微信入口仍需现场验收。

已有任务需要新增附件时，先确认任务未暂停，且工作目录未被其他任务占用，再附上文件并发送：

> 将本条消息的 data-v2.csv 上传到 task_… 的任务附件目录。确认文件已经写入后，继续原会话，改用这份数据重新分析。

附件上传和继续执行是两个动作。只有上传已确认，才能告诉 Codex 使用该文件。上传不会自动开始分析。已暂停的任务目前会拒绝上传；先让 Hermes 说明原状态和恢复计划，不要把上传失败当作文件已到位。

输入附件组总量最多 8 MiB，单次文件下载最多 8 MiB。附件写入任务工作目录中的 `.dots-duet/attachments/<任务编号>/<文件名>`，不会覆盖同名文件。文件名不能包含目录；同一任务需要新版本时使用新文件名。

文本读取使用 UTF-8；二进制文件使用下载。文件本身超过 8 MiB 时，不能靠分段读取绕过上限。目录单次最多列出 1000 项，超出会标记截断，当前不支持目录分页。

附件引用只对当前已授权消息有效。登记会过期；过期或更换消息后，请重新附上文件。只发一个电脑路径、转述另一人的文件路径或让模型猜缓存路径，都不能授予读取权。

创建或继续任务时，说明要交付的准确相对路径。任务文件读取和下载限制在其工作目录内，也可补取其中遗漏的文件。无任务时可以浏览授权文件夹的目录。下载后得到 服务器 上的私有副本；它与微信附件送达是两个状态。不要因文件获取失败而重跑已完成的原任务。

## 遇到问题与审批

Hermes 会先查证已有资料能回答的技术问题。目标、偏好、权限或需要你决定的事项，会在仍不能确定时交给你。回复时带上任务编号，并对准当前待处理问题。

Codex 原生审批必须由原用户确认。对于可表示为单次确认的命令或文件变更，Hermes 通过 MCP 请求你批准或拒绝该次请求。请核对对象和操作后，再使用客户端实际提供的确认界面；若官方给出 `/approve` 或 `/deny` 的当次确认提示，按该提示在原聊天回复。

普通文字“同意”、模型自己生成的批准决定、旧审批编号，都不能代替这次人工确认。取消确认、MCP 无法发起确认或请求需要更复杂的权限表单时，适配保留待处理请求。渠道未能显示确认提示、通知失败或超时时，应查询实际请求状态；Hermes 可能按拒绝处理，不能假定仍在等待。当前尚未通过真人微信审批验收。

## 怎样判断任务真的完成

| 看到的状态或结果 | 含义 |
| --- | --- |
| 已受理，或有 operation_id | 系统已记录这次操作；不表示 Codex 已完成。 |
| execution 为 starting / running | 原生执行正在启动或运行。 |
| execution 为 completed | 当前回合结束；业务目标仍需核验。 |
| waiting 有值 | 有待处理事项；让 Hermes 说明具体问题或审批。 |
| verification 为 passed | 已记录实际检查证据；仍需分别确认文件与交付。 |
| 文件 acquired，或完整下载成功 | Hermes 已取得校验后的私有副本。 |
| delivery 为 delivered | 原聊天发送队列已有所需的实际发送回执。 |
| unknown | 结果不确定；先查原记录，不能当作成功或未执行。 |
| pause_recorded 为 true | 已保存停止意图；仍需等待实际停止确认。 |
| stop_confirmed 为 true | 本次停止已核对到原生静止状态。 |

一次停止不会撤销已经完成的文件变更。恢复工作时，明确要求继续原任务；不要清空数据库或重新创建同名任务来“恢复”。

## 出现异常时

| 现象 | 处理方法 |
| --- | --- |
| 电脑离线 | 在自己的电脑确认执行端、网络和电源状态。恢复后先查询原任务。系统不会转用别人的电脑。 |
| 电脑在线，Codex 未就绪 | 检查该电脑上的 Codex 安装、登录和执行端日志。不要因为网络通了就重建任务。 |
| 文件夹或工作目录不可用 | 核对授权根、子目录及当前用户访问权。目录消失或被替换时不会自动改用其他位置。 |
| 提交后没收到明确结果 | 提供原任务和操作编号，让 Hermes 查询原收据。不要换编号重复提交。 |
| 文件只取得一部分 | 要求查看 offset、返回字节数和 truncated；部分内容不能作为完整产物。 |
| 文件已取回但聊天没收到 | 查询交付回执。结果 unknown 时先核对实际聊天，不自动重复发送。 |
| 提示来源未绑定或无权访问 | 请管理员检查真实用户、聊天、UID 和项目绑定。不要伪造身份字段绕过检查。 |
| 停止尚未确认 | 保留暂停意图，等待重连并查询原生状态。不要直接把项目交给冲突写任务。 |
| 自动恢复预算耗尽 | 根据实际错误决定修复环境、暂停或调整目标。反复重连不会重置预算。 |

报障时提供任务编号、操作编号、发生动作、实际错误和文件相对路径。不要提供 token、私钥、完整私有配置或他人的会话内容。

## 当前边界

本项目控制其专用 app-server 的任务。恢复历史会话与接管 Codex 桌面端正在运行的聊天不同，后者尚未验收。

当前以 Windows 执行端为实测对象。Hermes 更新、四个 profile 隔离和协议测试，不代表每个人的电脑都已开通，也不替代实际微信收发。具体缺口持续记录在[验收记录](验收记录.md)。
