# 部署与运行指南

执行端在用户自己的电脑上启动 Codex。管理员只需登记允许访问的文件夹根目录，任务可选择其中已有的子目录，不要求为每个工作项目另建绑定。Linux Hub 按实际 UID、私有执行端 token 和登记来源路由；各 Hermes profile 用自己的系统账号启动 MCP 和后台适配。

微信中的日常操作见[使用指南](使用指南.md)，完整验收状态见[验收记录](验收记录.md)。本文供管理员和执行电脑的所有者使用。真实部署记录使用仓库外的私有位置，或被忽略的 `deployments.local/`；不要把实际账号、地址、目录、来源 ID 或凭据写回公开文档。记录格式见[部署记录模板](部署记录模板.md)。配置示例是模板，不表示现网已登记这些绑定；不要直接粘贴占位符启动服务。

## 接入前先确定绑定

| 项目 | 谁提供，在哪里使用 |
| --- | --- |
| Linux UID、profile 名和实际 HOME | 管理员查实际系统账号；用于 Hub、Hermes 网关、MCP 和 worker。 |
| user_id、profile_id、executor_id | 管理员登记；Hub 与对应执行端的 scope 必须完全相同。 |
| 微信 platform、sender_id、chat_id | 从该 profile 的真实已授权来源核对；不是微信昵称，也不是模型生成值。 |
| 文件夹 ID 与绝对根目录 | 电脑所有者提供；Hub 登记 folder_ids，执行端 folders 登记同一 ID 与实际根目录。子目录无需再登记。 |
| 执行端 token | 管理员生成独立随机值，只写入 Hub 私有配置和对应电脑的 token 文件。 |
| 原生 API 地址、端口与 token 文件 | 每个 profile 独立配置，供自己的 worker 使用；不能共用别人的 API。 |

目前一个 Linux UID 只能有一条 binding，一条 binding 对应一台执行电脑，可登记多个文件夹根。Hub 拒绝重复 UID、执行端 ID 或 token。不要为同一 UID 复制多条绑定来添加电脑。

下例用 `owner-a`、`computer-a`、`projects` 和 `profile-a` 作为占位编号。配置时须核对真实使用者、来源和电脑；逻辑编号不要求与系统用户名相同。

跨机器协议现为版本 2。旧执行端不理解工作目录字段，Hub 会拒绝其握手；升级时必须一起更新 Hub 和执行端。数据库、scope、token 和操作编号保留。旧配置 projects/project_ids 与工具字段 project_id 仍可读取，但新配置使用 folders/folder_ids/folder_id；不要同时提供两套配置列表。

## 构建与检查

```powershell
New-Item -ItemType Directory -Path dist -Force
go test ./... -count=1
go vet ./...
go build -o dist/executor.exe ./cmd/executor
uv sync --project adapters/hermes --locked
uv run --project adapters/hermes python -m unittest discover -s adapters/hermes/tests -v
```

Hub 在 Linux 构建和运行。Windows 可交叉构建：

```powershell
$duetOldGOOS = $env:GOOS
$duetOldGOARCH = $env:GOARCH
try {
    $env:GOOS = 'linux'
    $env:GOARCH = 'amd64'
    go build -o dist/hub ./cmd/hub
    if ($LASTEXITCODE -ne 0) { throw 'Hub build failed' }
} finally {
    $env:GOOS = $duetOldGOOS
    $env:GOARCH = $duetOldGOARCH
}
```

构建依赖以 `go.mod`、`adapters/hermes/pyproject.toml` 和锁文件为准：Go 1.27.3，适配包 Python 3.14。上例构建 Linux amd64；目标平台不同则调整 GOARCH。Windows 用户运行发布二进制时不需要安装 Go 或适配包的 Python 环境。

普通测试不调用模型。真实集成测试只在显式设置 `DOTS_DUET_REAL_CODEX=1` 后运行；它使用临时项目，创建固定内容文件，再重启 app-server 并继续同一会话。不要把该变量配置为全局环境变量，也不要把真实模型检查当作无成本的健康检查。

## Linux Hub

Hub 使用独立的无特权账号。配置和 SQLite 目录只允许该账号访问。Unix socket 的父目录由 Hub 账号持有；各 profile 仅通过专用组取得 socket 访问权限，不取得配置和数据库权限。

Hub 配置文件权限必须为 600，账号必须可读。例子只展示一组绑定，`uid` 必须替换为运行目标 profile 的实际 UID：

```json
{
  "bindings": [{
    "uid": 1001,
    "user_id": "owner-a",
    "profile_id": "profile-a",
    "executor_id": "computer-a",
    "token": "REPLACE_WITH_A_PRIVATE_RANDOM_TOKEN",
    "folder_ids": ["projects"],
    "sources": [{
      "platform": "weixin",
      "sender_id": "REGISTERED_SENDER",
      "chat_id": "REGISTERED_CHAT"
    }]
  }],
  "followup_budget": 8
}
```

执行端只取得自己这一组 token。不要把整个 Hub 配置同步到执行电脑或 profile。Hub 拒绝 UID 0、重复 UID、重复执行端和重复 token。

```sh
/opt/dots-duet/bin/hub \
  -config /var/lib/dots-duet/hub.json \
  -state /var/lib/dots-duet/hub.sqlite \
  -socket /run/dots-duet/hub.sock \
  -listen TAILSCALE_IP:8025
```

该命令必须以 Hub 的无特权账号执行，直接用 root 启动会被拒绝。`TAILSCALE_IP` 替换为 服务器 的实际受控网络地址。TCP 端口只接执行端的 WebSocket，不提供 Hermes 工具 HTTP API；工具 API 仅在 Unix socket。当前 Hub 不自行配置 TLS，应只在已授权的受控网络内开放此监听。

### 账号、权限与 systemd

以下是管理员执行的 Bash 示例；默认 shell 为 fish 时先进入 Bash。`dots-duet` 是拟新建的 Hub 专用账号和组，不是现有 Hermes profile。先检查是否存在，已有账号时复用正确账号，不重复创建：

```bash
getent passwd dots-duet
getent group dots-duet
```

确认尚不存在后才创建，并准备私有状态目录：

```bash
sudo useradd --system --user-group --home-dir /var/lib/dots-duet \
  --create-home --shell /usr/bin/nologin dots-duet
sudo install -d -o dots-duet -g dots-duet -m 0700 /var/lib/dots-duet
sudo install -d -o root -g root -m 0755 /opt/dots-duet/bin
```

由管理员把对应 Linux Hub 二进制安装为 `/opt/dots-duet/bin/hub`，owner 为 root、模式为 755。把填写后的配置安装为 `/var/lib/dots-duet/hub.json`，owner 为 dots-duet、模式为 600。不要把配置放进代码仓库。

每个实际接入的 profile 账号加入仅用于访问 socket 的组。例如 profile profile-a 的实际系统账号是 `hermes-profile-a`：

```bash
sudo usermod -aG dots-duet hermes-profile-a
```

其他 profile 按实际账号逐个加入。它们只能访问 `/run/dots-duet/` 和 socket，不应读 Hub 的私有配置与 SQLite。补充组变更须在新进程中生效；安排维护窗口重新启动相应网关、MCP 和 worker，再检查其实际组成员。不要给 profile sudo。

`/etc/systemd/system/dots-duet-hub.service` 示例：

```ini
[Unit]
Description=dots-lite Hub
Wants=network-online.target
After=network-online.target

[Service]
User=dots-duet
Group=dots-duet
WorkingDirectory=/var/lib/dots-duet
RuntimeDirectory=dots-duet
RuntimeDirectoryMode=0750
UMask=0077
NoNewPrivileges=yes
CapabilityBoundingSet=
AmbientCapabilities=
ExecStart=/opt/dots-duet/bin/hub -config /var/lib/dots-duet/hub.json -state /var/lib/dots-duet/hub.sqlite -socket /run/dots-duet/hub.sock -listen TAILSCALE_IP:8025
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

替换监听地址并检查权限后，加载与查看日志：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now dots-duet-hub.service
systemctl status dots-duet-hub.service --no-pager
journalctl -u dots-duet-hub.service -n 80 --no-pager
stat -c '%U %G %a %n' /run/dots-duet /run/dots-duet/hub.sock
```

目录应为 Hub 账号与专用组持有、模式 750；socket 为同一账号与组持有、模式 660。systemd active 只证明进程在运行，接入是否正确还须由真实 profile 调用机器和项目查询确认。Hub 不提供 `/health` HTTP 路由。

配置只在启动时读取。更改绑定或 token 后，应先核对受影响任务和暂停需求，再在维护窗口重启 Hub；Windows 同时更新自己的配置或 token 文件并重启执行端。不要复用其他用户的 scope、数据库或凭据。

Hub 每 30 秒只读补查未结束或不确定的操作和任务。它不会重发未知写操作。服务异常退出留下的同属本账号的失效 socket 可以恢复；活跃 socket、普通文件和其他用户的 socket 不会被替换。

## Windows 执行端

先准备实际存在且已授权的项目，以及该电脑自己的 Codex 安装与登录。配置文件与 token 文件保存在当前普通用户的私有目录；Windows 需检查实际 ACL，不能用 Linux 的 600 模式替代。下面的 `C:\private\dots-duet` 是路径示例，须先建立并确认只有该用户及必要管理员可以访问：

```json
{
  "scope": {
    "user_id": "owner-a",
    "profile_id": "profile-a",
    "executor_id": "computer-a"
  },
  "folders": [{
    "id": "projects",
    "root": "C:\\workspaces",
    "approval_policy": "on-request",
    "sandbox": "workspace-write"
  }],
  "state_path": "C:\\private\\dots-duet\\executor.sqlite",
  "hub_url": "ws://TAILSCALE_IP:8025/v1/executor",
  "token_file": "C:\\private\\dots-duet\\token",
  "codex": "codex"
}
```

`scope` 和 token 必须与 Hub 登记相同。token 文件只放对应的原始 token，允许末尾换行；文件不可超过 4096 字节。`codex` 是可执行程序路径，不是带参数的整条启动命令。建议填写实际绝对路径，避免计划任务的 PATH 与交互终端不同。

JSON 拒绝未知字段；不能添加 `env` 或 `CODEX_HOME` 字段。执行端继承启动进程的 PATH、CODEX_HOME 和代理环境。文件夹根必须为绝对路径，ID 不能重复；根目录暂不可用时保持服务连接并报告不可用，不自动创建根或子目录。

任务创建时，`duet_prepare(action="task.create", folder_id="projects", working_directory="demo", input="...")` 选择授权根内已有的 demo 文件夹；省略 working_directory 表示根目录本身。只接受以正斜杠分隔的相对路径，例如 team/demo。绝对路径、`..`、盘符和越界链接会被拒绝。

工作目录创建后固定，不可通过继续、追加、上传或查询改换。文件路径、输入附件和自动产物都相对任务工作目录；冲突占用按实际目录判断，兄弟目录可分别运行，同目录及父子目录仍受保护。未知写结果仍保守阻塞同一授权根的新写，直到原操作得到核对。

### 先检查本机，再检查远端

在将来运行常驻执行端的同一用户、同一环境中检查：

```powershell
$env:CODEX_HOME = Join-Path $HOME '.codex'
& 'C:\apps\dots-duet\executor.exe' -probe -codex 'C:\实际路径\codex.exe' -timeout 30s
$LASTEXITCODE
```

`-probe` 与 `-config` 互斥。`-codex` 和 `-timeout` 只影响 probe；常驻执行使用 JSON 中的 `codex`。CODEX_HOME 应换成该用户实际登录所用目录。

probe 创建独立 app-server，只做初始化和账号配置读取，不运行模型。检查其 JSON 内容，不能只看退出码：

| 字段 | 解释 |
| --- | --- |
| initialized | 这次独立 app-server 已完成初始化。 |
| accountConfigured | 原生接口是否返回账号；false 时也可能正常退出，应继续核对实际认证方式。 |
| requiresOpenaiAuth | 原生接口报告的认证要求，不能单凭此字段判定模型可用。 |
| inferenceVerified | 固定为 false，probe 没有验证实际推理。 |
| desktopChatAttached | 固定为 false，没有接管桌面活跃聊天。 |

probe 不读常驻配置，不验证 Hub、token、文件夹权限或实际模型任务。随后可先检查 TCP 可达，再启动服务：

```powershell
Test-NetConnection 服务器 -Port 8025
& 'C:\apps\dots-duet\executor.exe' -config 'C:\private\dots-duet\executor.json'
```

网络检查通过不表示认证或目录就绪。让对应 profile 通过 Hermes 查询 `machine` 和 `folders`：需要 connected 为 true、snapshot.initialized 为 true，并且目标授权根 available 为 true。创建任务前可用 `duet_query(query="directory", folder_id="projects", path=".")` 浏览授权根；无任务时只开放目录浏览，文本和下载仍须带任务编号。查询本身不新建 Codex 模型回合。

### 配置常驻与停止

当前没有安装 Windows Service 或注册计划任务的 CLI。可在任务计划程序中手动配置：

| 选项 | 设置 |
| --- | --- |
| 运行用户 | 拥有该项目和 Codex 登录的当前普通用户，不勾选最高权限。 |
| 触发器 | 该用户登录时。电脑休眠、关机或用户未登录时，不能据此承诺在线。 |
| 程序 | 下方编译的 `WindowsServiceLauncher.exe` 绝对路径。 |
| 参数 | PowerShell 与启动脚本的两个绝对路径，各自加引号，例如 `"C:\Program Files\PowerShell\7\pwsh.exe" "C:\apps\dots-lite\start-executor.ps1"`。 |
| 起始位置 | 实际存在的工作目录，例如 `C:\apps\dots-duet`。 |
| 失败重启 | 按本机维护策略启用。 |
| 已在运行时 | 不启动新实例；一份配置和数据库只运行一个执行端。 |

Windows Terminal 作为默认终端时，计划任务直接启动 `pwsh -WindowStyle Hidden` 仍可能出现常驻窗口。使用[无控制台启动入口](../skills/dots-lite-deploy/assets/WindowsServiceLauncher.cs)，从项目根目录编译到已创建的服务 bin 目录：

```powershell
$duetCsc = Join-Path ([Environment]::GetFolderPath('Windows')) 'Microsoft.NET\Framework64\v4.0.30319\csc.exe'
if (-not (Test-Path -LiteralPath $duetCsc)) { throw '缺少 Windows .NET Framework C# 编译器。' }
& $duetCsc /nologo /target:winexe /optimize+ /out:"C:\apps\dots-lite\bin\WindowsServiceLauncher.exe" skills\dots-lite-deploy\assets\WindowsServiceLauncher.cs
if ($LASTEXITCODE -ne 0) { throw '启动入口编译失败。' }
```

必须使用 `winexe`，使计划任务入口本身没有控制台。入口以 `CreateNoWindow=true` 启动 PowerShell，等待其退出并传回原退出码；启动失败写入相对 bin 的 `..\logs\launcher-host.log` 并返回 1。这样保留计划任务的运行状态和失败重启，不通过修改全局默认终端解决。

在该用户的 PowerShell 启动脚本中设置必要的 CODEX_HOME、代理和子进程环境，再以无窗口方式调用执行端的 `-config` 命令，并保存 stdout/stderr。脚本等待执行端是正常的，不应为了关闭窗口而提前结束。不要以 SYSTEM 或管理员身份绕过 Codex 权限。程序没有额外 `-log-file` 参数。

暂停单项工作应经 Hermes 调用业务停止，查看 pause_recorded 与 stop_confirmed。前台 Ctrl+C 会关闭整个执行端及其持有的 app-server 进程树，不能替代业务停止确认。长期停用前还应禁用自动启动任务；程序没有 `executor stop` 子命令。

执行端只在确认原进程已退出且资源清理完成后自动重启 app-server。累计最多三次，保存在本地 SQLite 中；网络重连和服务重建不会补充次数。预算耗尽后仍可查询错误；用户显式重新启动服务可启动一次原生接口，但不会恢复自动重启预算。未知操作、暂停意图和项目占用均保留，不重放旧回合。

## Hermes

每个非 default profile 使用独立 Linux 账号、私有 `HERMES_HOME` 和工作目录。不要给这些账号 sudo、管理员密钥或可修改公共服务的权限。默认 profile 不因这些配置自动接入 Dots。

### 安装适配包与来源插件

将代码安装到管理员持有、profile 不能修改的目录。以下统一使用 `/opt/dots-duet/source` 作为代码目录，并在 Linux 构建机上安装锁定的适配包：

```bash
umask 022
uv sync --project /opt/dots-duet/source/adapters/hermes --locked --link-mode copy
```

MCP 和 worker 使用此环境的 Python。公共目录须能由 profile 进入，程序和依赖须可读、不可写。部署后以实际 profile UID 检查模块导入；root 缓存的文件权限可能过严，不能仅凭 root 安装成功就判断其他 UID 可用。来源插件只使用标准库，不需要把 MCP SDK 装入 Hermes 自身的 Python。

在对应 profile 的用户环境中，将整个 `adapters/hermes/src/dots_lite_hermes/` 目录复制或链接到 `$HERMES_HOME/plugins/dots-duet`。目录内必须同时有 `plugin.yaml`、`__init__.py` 和其他模块；不要只复制 plugin.py。目标已存在时先核对，不覆盖无关插件。官方目录插件加载此路径，不能把本地目录当作插件市场名称安装。

插件声明 `pre_gateway_dispatch`、`post_gateway_admission`、`pre_tool_call` 三个 hook。它从当前原生消息读取可信来源；缺少绑定时明确拒绝操作。安装后应检查官方插件列表与诊断，确认插件已启用且三个 hook 均加载，再安排网关重新加载。

下面的命令在该 profile 实际 UID 的环境中执行，HOME 与 HERMES_HOME 必须已正确设置。管理员可用 `sudo -u <实际账号> env ...` 启动该环境；profile 本身不需要 sudo：

```bash
mkdir -p "$HERMES_HOME/plugins"
ln -s /opt/dots-duet/source/adapters/hermes/src/dots_lite_hermes \
  "$HERMES_HOME/plugins/dots-duet"
/opt/hermes/.venv/bin/hermes plugins enable dots-duet
/opt/hermes/.venv/bin/hermes plugins list
```

仅在目标不存在时执行 ln。此操作启用插件时应保留原有插件列表，尤其是既有微信插件。可用官方 `hermes plugins doctor <插件目录>` 核对安装；目录传实际 `$HERMES_HOME/plugins/dots-duet`。

### 配置网关环境与 MCP

原生 MCP 服务器名称必须为 `dots_duet`。把以下内容合并到该 profile 的私有 config.yaml，保留现有其他工具配置。以下统一以 profile-a 与示例系统账号 hermes-profile-a 展示布局，必须替换为目标环境的实际值：

```yaml
mcp_servers:
  dots_duet:
    command: /opt/dots-duet/source/adapters/hermes/.venv/bin/python
    args: ["-m", "dots_lite_hermes"]
    env:
      HOME: /var/lib/hermes-profile-a
      HERMES_HOME: /var/lib/hermes-profile-a/.hermes/profiles/profile-a
      DOTS_DUET_SOCKET: /run/dots-duet/hub.sock
      DOTS_DUET_FILES_DIR: /var/lib/hermes-profile-a/.hermes/profiles/profile-a/dots-duet/files
    timeout: 240
    elicitation:
      enabled: true
      timeout: 180
```

同时在 **Hermes 网关父进程** 的 systemd 环境中固定同一组 HOME、HERMES_HOME、DOTS_DUET_SOCKET 和 DOTS_DUET_FILES_DIR。只写 mcp_servers 的 env 不够：来源插件运行在网关中，也需要自己连接 Hub。MCP、网关、worker 应使用同一实际 profile UID，并指向同一私有文件目录。

上例给 MCP 调用 240 秒、人工确认 180 秒；两者均小于 Hub 默认 300 秒的调用引用有效期。字段是 `timeout`，不是 `tool_timeout`。审批还依赖当前 Hermes 渠道实际提供的人工确认能力，配置开启不能代替真人验收。

`DOTS_DUET_FILES_DIR` 的目录模式为 700，文件为 600，由该 profile 持有；不同 profile 不共用目录。父目录必须可由该账号访问。不要让 MCP 使用 Hub 的服务账号或管理员账号运行。

重载后确认 Hermes 可发现以下七个工具：

| 工具 | 用途 |
| --- | --- |
| duet_query | 查询机器、授权文件夹、任务、会话、Goal、待处理请求和文件。 |
| duet_prepare | 登记创建、继续、追加、Goal 或附件操作；此时不执行。 |
| duet_submit | 按已保存的 operation_id 执行一次登记操作。 |
| duet_stop | 保存任务暂停意图，核对原生 Goal 和回合停止。 |
| duet_answer | 回答结构化问题，不授予操作权限。 |
| duet_approve | 请求原用户对当前单次审批作真实确认。 |
| duet_record | 保存实际核验或跟进证据；模型不能自报微信已送达。 |

工具发现不等于来源登记成功；还须在真实、已授权的消息上下文中查询。不要复制测试脚本里的 fixture 来源到生产配置，也不要给模型手工填写 `_context_ref`。

以该 profile 用户、同一环境运行官方只读连接检查：

```bash
/opt/hermes/.venv/bin/hermes mcp list
/opt/hermes/.venv/bin/hermes mcp test dots_duet
```

直接工具展示和官方 Tool Search 桥接有不同发现路径。部署时核对所用模式下工具实际可见，保留已有选择；工具发现不能代替真实模型调用验收。

### 配置原生 API 与后台 worker

后台适配使用该 profile 的原生 API，配置独立 API token 和回环地址。API 必须声明持久幂等支持。初次提交前就固定 run 的 session 与幂等键；失败后的新诊断尝试使用新引用，并保留旧证据。默认每项任务最多八个原生跟进、二十四次尚未取得 run 编号的受理尝试以及一小时恢复窗口；已有 run 的只读状态轮询不消耗受理次数，也不重置预算。

服务器当前 Hermes 的 API 密钥放在该 profile 的私有环境中。这里的 token 是占位符，须换成独立随机值，至少 16 个字符；每个 profile 使用不同 token 和不同回环端口：

```dotenv
API_SERVER_KEY=REPLACE_WITH_A_PRIVATE_RANDOM_API_TOKEN
```

在对应 profile 的 config.yaml 合并：

```yaml
platforms:
  api_server:
    enabled: true
    extra:
      host: 127.0.0.1
      port: 8642
```

密钥由该 profile 私有 `.env` 提供，不写入公共配置、unit 命令行或仓库。上例把 host 和 port 统一放在 YAML。已有的有效 `API_SERVER_HOST`、`API_SERVER_PORT` 环境值会覆盖 YAML，须删除这些旧覆盖项或同步改为一致，不能只改 YAML。当前版本没有 `API_SERVER_ENABLED` 开关。需明确配置网关启用 `api_server`；保留已有微信和其他平台设置。原生 API 的启动和端口变更与网关在维护窗口一起处理，避免同机多个 profile 端口冲突。

把同一裸 token 写入下方 `--api-token-file` 指向的私有文件，不能写成 `API_SERVER_KEY=...` 一整行。worker 的 URL 使用 API 根地址，不加 `/v1`。带认证的只读 `GET /v1/capabilities` 应报告 `features.runs_idempotency.supported=true` 且 `durable=true`；否则停止接入并检查该 profile 的原生状态目录写权限。仅 API 启动成功不足以证明持久幂等可用，状态写入失败时原生接口可能回退到内存。

worker 命令须固定官方 Hermes Python 和源码路径，用于原聊天发送。下面使用示例运行时路径；API 地址、运行时和 token 文件均须按实际配置替换：

```bash
/opt/dots-duet/source/adapters/hermes/.venv/bin/python \
  -m dots_lite_hermes worker \
  --socket /run/dots-duet/hub.sock \
  --api-url http://127.0.0.1:8642 \
  --api-token-file /var/lib/hermes-profile-a/.hermes/profiles/profile-a/dots-duet/api-token \
  --hermes-python /opt/hermes/.venv/bin/python \
  --hermes-source /opt/hermes
```

worker 每个 profile 只启动一份，使用该 profile 的 UID、HOME、HERMES_HOME 和 DOTS_DUET_FILES_DIR，并取得 socket 专用组权限。参数由管理员配置，模型不能选择。token 文件必须为该账号可读的私有文件，模式 600。不要把所有 profile 的 token 放到共享文件中。

用 systemd 常驻的示例 `/etc/systemd/system/dots-duet-worker-profile-a.service` 如下。只适用于示例 profile；其他 profile 要逐项替换 User、Group、HOME、HERMES_HOME、文件目录、工作目录、API 端口与 token 文件。

```ini
[Unit]
Description=dots-lite worker for profile profile-a
After=dots-duet-hub.service hermes-profile-a.service

[Service]
User=hermes-profile-a
Group=hermes-profile-a
SupplementaryGroups=dots-duet
WorkingDirectory=/var/lib/hermes-profile-a/workspace
Environment=HOME=/var/lib/hermes-profile-a
Environment=HERMES_HOME=/var/lib/hermes-profile-a/.hermes/profiles/profile-a
Environment=DOTS_DUET_SOCKET=/run/dots-duet/hub.sock
Environment=DOTS_DUET_FILES_DIR=/var/lib/hermes-profile-a/.hermes/profiles/profile-a/dots-duet/files
Environment=GATEWAY_MULTIPLEX_PROFILES=false
UMask=0077
NoNewPrivileges=yes
CapabilityBoundingSet=
AmbientCapabilities=
ExecStart=/opt/dots-duet/source/adapters/hermes/.venv/bin/python -m dots_lite_hermes worker --socket /run/dots-duet/hub.sock --api-url http://127.0.0.1:8642 --api-token-file /var/lib/hermes-profile-a/.hermes/profiles/profile-a/dots-duet/api-token --hermes-python /opt/hermes/.venv/bin/python --hermes-source /opt/hermes
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

确认 Hub、该 profile 网关与 API 均可用，且允许 worker 处理真实队列后，由管理员 `systemctl daemon-reload` 并 `systemctl enable --now dots-duet-worker-profile-a.service`。查看 `journalctl -u dots-duet-worker-profile-a.service -n 80 --no-pager`。其 active 状态只证明 worker 进程存在，还要检查日志与实际业务回执。

`--once` 会真实处理一次待办，可能取得产物、调用模型或向原聊天发送消息，**不是只读健康检查**。常驻模式每五秒查询，错误写标准错误。不要为了测试安装而对生产队列试跑 worker。

worker 先取得并校验产物，再发送原聊天 outbox，最后处理原生跟进。最终文字与当前授权产物均有实际原生回执后，才报告 delivered。单元在发送前持久登记；重启或超过 150 秒未得回执则为 unknown，不自动重发。只有发送前明确未发出才可在累计三次预算内重试。

完整工具、插件、文件与原生运行说明见 [Hermes 适配说明](../adapters/hermes/README.md)。

## 文件、审批与未知结果

单文件上限为 8 MiB，传输帧和 HTTP 正文上限为 16 MiB。下载检查完整性、实际字节数和 SHA-256，私有副本使用目录 700、文件 600。部分范围明确标记为截断。获取文件不等于目标核验通过或微信交付成功。

文件操作使用任务工作目录内的相对路径。无任务的目录浏览须指定已授权 folder_id；不能借此进行文本读取或下载。超过 8 MiB 的文件不能靠分段读取绕过限制；文本范围必须是有效 UTF-8，二进制用下载。范围读取的哈希对应实际返回字节。目录单次最多 1000 项，超出会标记截断，当前不提供目录分页。

新任务可在 `duet_prepare(action="task.create", inputs=[{name,local_path}], ...)` 引用本条已授权消息的附件；既有任务用 `files.upload`。来源插件通过官方 admission hooks 私下读取稳定文件快照，模型只传引用。每组输入总量最多 8 MiB。文件写入任务工作目录的 `.dots-duet/attachments/<task-id>/<name>`，不覆盖；新任务全部落地后才启动原生会话。prepare 不写文件，同一 operation 重试返回原收据。读写均受实际目录句柄约束。

既有任务上传要求任务未暂停且目录未被其他任务占用。暂停任务的上传会拒绝；不要把“上传后继续”的流程直接套在已暂停任务上。部分输入写入失败会保留已经写入的事实，先查询原操作，不自动回滚或重做。

原生审批仍需原用户在原聊天中完成单项确认。模型不能提供批准决定。停止时先保存暂停版本，再核对 Goal 和实际回合；存在未决原生写操作时不会提前确认静止或释放项目。

未知结果先查询原操作与实际状态，不换编号重做。故障、缺少证据、文件未取得和发送未确认都保留各自状态，不合并为“完成”。

## 接入顺序与检查

1. 确认真实微信来源、系统 UID、执行电脑和项目，填写 Hub 与执行端配置。
2. 启动 Hub，核对 socket 权限；安装并启用该 profile 的来源插件和 MCP。
3. 配置同 profile 的原生 API 和 worker，但在允许处理该 profile 的真实队列后再启动 worker。
4. 在 Windows 以原用户运行 probe，再启动一份常驻执行端。
5. 从真实授权聊天查询机器与项目；确认三项就绪后，再按[使用指南](使用指南.md)创建明确授权的最小任务。
6. 分别核对实际文件、Hermes 私有副本和微信回执，不能只检查模型文字。再检验同任务继续、追加、停止和所需的人工审批。
7. 用第二名用户及其另一台电脑验证路由隔离；不得读取或操作对方任务。

真实任务可能调用付费模型、修改项目或发送微信。上述现场检查按实际授权逐项执行；普通构建、配置语法检查和工具列表不替代这些结果。

## 排查与维护

| 现象 | 先检查 |
| --- | --- |
| Unix socket permission denied | 父目录 750、socket 660、专用组，以及网关/MCP/worker 新进程的实际补充组。不要改成 777。 |
| caller has no binding | Hub 配置的 UID 是否等于调用进程实际 UID；不要以 root 代替 profile 测试。 |
| message source is not bound | 原生消息的 platform、sender_id、chat_id 与登记值；不要用昵称或伪造 HTTP 身份替代。 |
| Missing trusted context / invalid_context | 插件是否加载、网关是否有 DOTS_DUET_SOCKET、是否在当前真实消息上下文内调用。 |
| 工具列表缺少 dots_duet | MCP Python 路径、依赖、进程环境、原生工具发现与 Tool Search 的可见范围。列出工具成功不代表模型已实际调用。 |
| 执行端认证被拒 | Hub token 与该电脑 token 文件、重复连接、scope；认证失败会退出，网络故障才会重连。 |
| connected=true 但 initialized=false | snapshot.error 与 Windows 标准错误；查看 Codex 启动环境和实际可执行路径。 |
| 业务核验不推进 | worker 日志、该 profile 原生 API、持久幂等能力和真实工具发现；不要另建一轮 Codex 任务掩盖旧错误。 |
| 已取文件但未发送 | 产物完整性、原聊天目标、worker sender 和交付回执。unknown 时先核对实际聊天。 |
| unknown 或停止未确认 | 保留数据库，查询原操作、session 与 Goal，等待原执行端核对。不要直接删除 SQLite 或换操作编号重试。 |

修改配置或更新程序前，先查询受影响任务并按需要请求业务停止，确认原生静止，再停对应服务。关闭服务后备份其私有配置、数据库、附件和所需状态；SQLite 使用 WAL，不能在运行中只复制主文件来充当完整备份。备份仍应私有持有。

更新后继续使用原 scope、state_path、数据库和任务编号，先查询原状态，再恢复已授权工作。仓库无一键迁移、凭据重置或清零恢复预算的 CLI，不应把旧验收脚本当成生产升级入口。
