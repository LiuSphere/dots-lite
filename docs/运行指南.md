# 运行指南

执行端在用户自己的电脑上启动 Codex。Linux Hub 按实际 UID、私有执行端 token 和登记来源路由；各 Hermes profile 用自己的系统账号启动 MCP 和后台适配。

完整验收状态见[验收记录](验收记录.md)。下例中的账号、路径、地址和 token 必须按实际绑定配置，不能让模型选择或补填。

## 构建与检查

```powershell
go test ./... -count=1
go vet ./...
go build -o dist/executor.exe ./cmd/executor
uv sync --project adapters/hermes --locked
uv run --project adapters/hermes python -m unittest discover -s adapters/hermes/tests -v
```

Hub 在 Linux 构建和运行。Windows 可交叉构建：

```powershell
$env:GOOS = 'linux'
go build -o dist/hub ./cmd/hub
Remove-Item Env:\GOOS
```

普通测试不调用模型。真实集成测试只在显式设置 `DOTS_DUET_REAL_CODEX=1` 后运行；它使用临时项目，创建固定内容文件，再重启 app-server 并继续同一会话。不要把该变量配置为全局环境变量。

## Linux Hub

Hub 使用独立的无特权账号。配置和 SQLite 目录只允许该账号访问。Unix socket 的父目录由 Hub 账号持有；各 profile 仅通过专用组取得 socket 访问权限，不取得配置和数据库权限。

Hub 配置文件权限必须为 600。例子只展示一组绑定：

```json
{
  "bindings": [{
    "uid": 1001,
    "user_id": "owner-a",
    "profile_id": "owner-a",
    "executor_id": "computer-a",
    "token": "REPLACE_WITH_A_PRIVATE_RANDOM_TOKEN",
    "project_ids": ["main-project"],
    "sources": [{
      "platform": "weixin",
      "sender_id": "REGISTERED_SENDER",
      "chat_id": "REGISTERED_CHAT"
    }]
  }],
  "followup_budget": 8
}
```

执行端只取得自己这一组 token。不要把整个 Hub 配置同步到执行电脑或 profile。Hub 拒绝 UID 0、重复 UID、重复执行端和重复 token。

```sh
/opt/dots-duet/bin/hub \
  -config /var/lib/dots-duet/hub.json \
  -state /var/lib/dots-duet/hub.sqlite \
  -socket /run/dots-duet/hub.sock \
  -listen TAILSCALE_IP:8025
```

将这个命令交给 systemd 常驻管理，并设置正确的 `User`、`Group`、`UMask=0077`、`NoNewPrivileges=yes` 及空 capability 集合。二进制和公共代码由管理员持有，profile 不能修改。配置目录不与 socket 目录共用权限。

Hub 每 30 秒只读补查未结束或不确定的操作和任务。它不会重发未知写操作。服务异常退出留下的同属本账号的失效 socket 可以恢复；活跃 socket、普通文件和其他用户的 socket 不会被替换。

## Windows 执行端

先准备实际存在且已授权的项目。配置文件与 token 文件保存在用户私有目录：

```json
{
  "scope": {
    "user_id": "owner-a",
    "profile_id": "owner-a",
    "executor_id": "computer-a"
  },
  "projects": [{
    "id": "main-project",
    "root": "C:\\work\\authorized-project",
    "approval_policy": "on-request",
    "sandbox": "workspace-write"
  }],
  "state_path": "C:\\private\\dots-duet\\executor.sqlite",
  "hub_url": "ws://TAILSCALE_IP:8025/v1/executor",
  "token_file": "C:\\private\\dots-duet\\token",
  "codex": "codex"
}
```

`scope` 和 token 必须与 Hub 登记相同。`codex` 使用该电脑自己的安装与登录。项目暂不可用时保持服务连接并报告不可用，不自动创建项目目录。

```powershell
C:\apps\dots-duet\executor.exe -probe
C:\apps\dots-duet\executor.exe -config C:\private\dots-duet\executor.json
```

常驻运行可使用当前用户的 Windows 计划任务：登录时启动执行端，运行级别选择普通用户，并设置异常退出后重启。计划任务调用同一条 `-config` 命令，不依赖打开的终端。不要以 SYSTEM 或管理员身份运行来绕过 Codex 权限。

执行端只在确认原进程已退出且资源清理完成后自动重启 app-server。累计最多三次，保存在本地 SQLite 中；网络重连和服务重建不会补充次数。预算耗尽后仍可查询错误；用户显式重新启动服务可启动一次原生接口，但不会恢复自动重启预算。未知操作、暂停意图和项目占用均保留，不重放旧回合。

## Hermes

每个非 default profile 使用独立 Linux 账号、私有 `HERMES_HOME` 和工作目录。不要给这些账号 sudo、管理员密钥或可修改公共服务的权限。默认 profile 不因这些配置自动接入 Dots。

原生 MCP 服务器名称为 `dots_duet`。命令是锁定环境的 `python -m dots_duet_lite_hermes`，环境固定 `DOTS_DUET_SOCKET`。官方目录插件从 `adapters/hermes/src/dots_duet_lite_hermes/` 加载；插件必须能读取当前原生绑定的来源，缺少来源时拒绝操作。

后台适配使用该 profile 的原生 API，配置独立 API token 和回环地址。API 必须声明持久幂等支持。初次提交前就固定 run 的 session 与幂等键；失败后的新诊断尝试使用新引用，并保留旧证据。默认每项任务最多八个原生跟进、二十四次尚未取得 run 编号的受理尝试以及一小时恢复窗口；已有 run 的只读状态轮询不消耗受理次数，也不重置预算。

worker 命令须固定官方 Hermes Python 和源码路径，用于原聊天发送：`python -m dots_duet_lite_hermes worker --socket /run/dots-duet/hub.sock --api-url http://127.0.0.1:8642 --api-token-file /private/profile/api-token --hermes-python /opt/hermes/venv/bin/python --hermes-source /opt/hermes/source`。这些参数由管理员配置，模型不能选择。

worker 先取得并校验产物，再发送原聊天 outbox，最后处理原生跟进。最终文字与当前授权产物均有实际原生回执后，才报告 delivered。单元在发送前持久登记；重启或超过 150 秒未得回执则为 unknown，不自动重发。只有发送前明确未发出才可在累计三次预算内重试。

完整工具、插件、文件与原生运行说明见 [Hermes 适配说明](../adapters/hermes/README.md)。

## 文件、审批与未知结果

单文件上限为 8 MiB，传输帧和 HTTP 正文上限为 16 MiB。下载检查完整性、实际字节数和 SHA-256，私有副本使用目录 700、文件 600。部分范围明确标记为截断。获取文件不等于目标核验通过或微信交付成功。

新任务可在 `duet_prepare(action="task.create", inputs=[{name,local_path}], ...)` 引用本条已授权消息的附件；既有任务用 `files.upload`。来源插件通过官方 admission hooks 私下读取稳定文件快照，模型只传引用。每组输入总量最多 8 MiB。所有文件写入任务的 `.dots-duet/attachments/<task-id>/<name>`，不覆盖；新任务全部落地后才启动原生会话。prepare 不写文件，同一 operation 重试返回原收据。读写均受实际目录句柄约束。

原生审批仍需原用户在原聊天中完成单项确认。模型不能提供批准决定。停止时先保存暂停版本，再核对 Goal 和实际回合；存在未决原生写操作时不会提前确认静止或释放项目。

未知结果先查询原操作与实际状态，不换编号重做。故障、缺少证据、文件未取得和发送未确认都保留各自状态，不合并为“完成”。

## hub-server 本轮切换后的状态

hub-server 的 Hermes 使用独立 stable v0.22.5 运行时 `/opt/hermes-agent-v0.22.5`，公共 Node、Skills、浏览器及 MCP 程序位于 `/opt/hermes/shared-tools`，均由管理员持有。四个非 default profile 的实际 UID 为：owner-a 1001、profile-b 1002、profile-c 1003、profile-d 1004。`getent passwd <UID>` 可查看当前账号和 HOME。default 仍使用原 UID 1000。

各命名 profile 保留 `HOME/.hermes/profiles/<原名>` 布局，设置 `GATEWAY_MULTIPLEX_PROFILES=false` 和官方 `gateway.standalone=true`。网关以相应 UID 运行，UMask=0077、NoNewPrivileges=yes。不要再从 default 的 CLI 或面板进入他人的旧 profile；旧目录已保存在 root 私有回滚目录。

Playwright 使用已安装的固定 `@playwright/mcp@0.0.83`，不在运行中临时拉取其他版本。Deepwiki 的 mcp-remote 明确启用现有进程内代理；该设置只作用于它的 MCP 子进程。四个 UID 已实际列出对应工具。现有邮件脚本、认证和去重状态保留，没有通过标记邮件或向微信外发消息测试迁移。

本轮部署了 Hermes 更新和 profile 隔离。Dots 生产 Hub/执行端绑定仍须按实际用户、电脑和项目登记；本指南的绑定示例与已经清理的 fixture 环境均不自动授予现网访问权。完整检查及回滚位置见验收记录。
