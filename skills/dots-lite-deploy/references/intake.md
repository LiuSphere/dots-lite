# 参数收集

先从当前指令和可读配置填入已知值，一次询问一组缺失信息。技术事实自己检查，用户决定目标与权限。

## 首轮必要信息

| 信息 | 如何取得或询问 |
| --- | --- |
| 操作类型 | 新装、新增执行电脑或原部署更新；先查看现有服务，避免重复安装。 |
| SSH 连接 | 主机/IP或别名、端口、维护账号；已有别名可从本机配置解析。 |
| 免交互密钥 | 私钥的本机绝对路径，或用户明确指定的已解锁 agent 身份。登录不能要求密码或口令。私钥留本机，不上传服务器。 |
| sudo | 该账号是否具备部署所需免密 sudo，并实际用 `sudo -n` 检查。SSH 免口令和 sudo 免密码是两项条件。 |
| Hermes profile | 用户选择目标 profile；实际账号、UID、HOME、HERMES_HOME、网关 unit 自己核对，不从名称猜测。 |
| 本机部署目录 | 用户给绝对路径，例如 `C:\apps\dots-lite`。程序、配置、状态、日志和启动入口分子目录存放。 |
| 服务器部署目录 | 用户选择绝对路径，可建议 `/opt/dots-lite`。私有状态与 socket 可建议 `/var/lib/dots-lite`、`/run/dots-lite`，一并列入方案。更新优先沿用原路径。 |
| 授权文件夹 | 用户逐项给本机绝对路径，可多项。说明“包含子目录，无需逐个登记项目”。不从部署目录或仓库位置推断授权。 |
| 源码与版本 | 当前仓库正确则确认目标提交；否则要源码路径，或仓库地址与目标版本。 |

多项缺失时使用下面表单，只展示未填写字段：

```text
请补充部署信息。密钥只给本机路径，不要粘贴私钥或密码。

1. 服务器 SSH 地址/别名、端口、登录账号：
2. 私钥绝对路径或已解锁 SSH 身份；该账号是否有免密 sudo：
3. 要接入的 Hermes profile：
4. 本机服务部署目录、服务器程序部署目录：
5. 授权文件夹绝对路径，可多项，均包含子目录：
6. 如当前目录不是源码，请给源码路径或仓库与版本：
```

## 检查后按需补问

| 情况 | 用户需要决定的事项 |
| --- | --- |
| 授权根不存在 | 是否创建列出的空目录，不代替用户搬移现有项目。任务工作子目录必须已存在。 |
| 根重叠、ID 冲突或更新要撤销原根 | 给出合并或保留方案并检查关联任务，不能静默扩大授权或改绑旧任务。 |
| 多条网络路径 | 选择执行电脑可达的私网或受控隧道。Hub 当前不自行提供 TLS，不默认暴露公网明文端口。 |
| 要求自启 | 默认登录后隐藏运行。要求未登录也运行时，说明账号与系统方案再取得决定，不擅自改为 SYSTEM 或保存登录密码。 |
| 有任务、活动 Goal、待发送或未知操作 | 决定等待，还是对明确任务发起业务停止。服务关闭不证明业务停止。 |
| 真实来源有多个候选 | 用户确认自己的聊天/渠道，再从该 profile 的可信数据核对稳定 ID。昵称和 profile 名不是来源凭证。 |
| Hermes 缺失、版本不兼容、profile 共用账号 | 准备新装、升级或账号迁移的具体范围；接入一个 profile 不自动授权全机升级或其他 profile 迁移。 |
| Codex 未就绪 | 说明缺失条件；必要登录交互由用户完成。沿用原 CODEX_HOME、认证和 provider，不索要聊天中的 API 密钥。 |
| 审批或 sandbox 不同 | 默认提出 on-request 与 workspace-write；更改策略时说明范围并核对当前接口。 |
| 真实端到端验收 | 明确测试目录、模型调用、可修改文件、发送对象与消息/文件内容。允许模型调用不等于允许消息外发。 |

## 自己检查和生成

自己检查架构、可执行路径、端口、协议、锁文件、当前 Windows 用户、Linux UID/补充组、服务状态和权限。为新服务生成稳定 scope、folder ID、独立随机 token 与服务名，将映射列入方案。私密值不进入聊天、公共文档或 Git。

服务部署目录和授权工作目录是独立参数。服务器 MCP 的私有文件目录只存传输副本，不等于服务器获得了执行电脑工作目录的 SSH 权限。
