# dots-lite 部署

把用户的 Windows 执行电脑接到 Linux Hub 和指定 Hermes profile。交付可运行的后台服务、持久配对、明确的文件夹授权及实际验证记录。

此 skill 处理该项目的部署。源码功能开发、Hermes 核心修改、多 profile 迁移和真实消息外发分别按用户授权处理。用户只问方案或原理时保持只读；选择 skill 本身不代表批准生产变更。

## 1. 收集参数

先读当前仓库、已有配置和本轮指令，按[参数收集](references/intake.md)询问缺少的信息。已明确的选择直接沿用；从历史记录取得的主机、路径、账号和版本先现场复核。UID、可执行路径、端口占用等由自己检查，只问用户需要决定的事项。

至少确定 SSH 主机、账号、端口、免交互密钥的本机路径、目标 Hermes profile、本机与服务器部署目录、授权文件夹列表。只索要密钥路径或用户指定的已解锁 SSH 身份，不要求粘贴私钥或密码。

没有源码时询问本项目源码目录，或仓库地址与目标版本。以源码、锁文件、命令行帮助和部署文档为准，不把某次部署的主机别名、用户、UID、来源 ID、目录或 token 当作默认值。

完成条件：必要参数均有明确值或可核验来源；授权根是绝对路径，包含子目录的规则已说明。

## 2. 预检和准备

用指定身份验证 `ssh` 的 `BatchMode=yes` 登录，再检查 `sudo -n true` 与 `sudo -n -l`，确认所需部署命令可免密执行。指定密钥时设置 `IdentitiesOnly=yes`。首次连接核对可信指纹，不关闭主机身份检查。

连接或 sudo 失败时报告具体步骤，询问正确身份或管理员修复权限。不要输出私钥、改全局 SSH 配置、自动授予 sudo 或反复猜测身份。

读取[部署操作](references/deployment.md)，完成以下准备：

- 核对 Codex、Hermes、目标 profile 的真实环境，区分维护账号与业务账号。
- 核对受影响任务、原生活动和待发送队列，确定停启范围和备份方法。
- 生成本次参数对应的配置、启动入口、服务定义和发布包，完成构建及不调用模型、不发送消息的检查。
- 核对目录、端口和权限；现有数据、身份或授权范围存在冲突时，准备具体方案供用户决定。

完成条件：安装材料可审查；保留项、备份位置、受影响范围、停启顺序与回滚步骤明确。不能用清空状态或试跑生产 worker 代替预检。

## 3. 安装或切换

用户已批准同一主机、目录、profile 和范围的部署或重部署时，直接执行必要变更。仅在缺少生产变更授权、发现新的影响范围或需要用户决定时询问；提问前先完成不依赖回答的准备并展示具体变化。

先确认空闲或完成获准的业务停止，再备份、停受影响进程、替换并启动。双端协议必须兼容。更新保留 scope、token、来源、数据库和任务编号；新绑定生成独立凭据并写入私有文件。

本机按用户选择设置隐藏自启，默认当前普通用户登录触发，输出写日志。服务器业务服务使用无特权账号。授权根可有多个，每个根包含子目录，只开放用户选定的范围。

新失败保留原始错误和现场，先定位再修正。未知写入或消息结果先查询原记录，不换编号重做。少量调整后仍无法核实则停止该步骤，报告已完成部分及阻塞原因；不把不断重启的进程写成部署成功。

## 4. 验证和交付

依照部署操作验收进程、认证连接、Codex 初始化、授权目录、Hermes 工具和后台处理条件。以业务实际 UID 检查权限与 MCP，root 成功不能代替业务账号验收。

默认不创建真实模型任务、不向联系人发送测试消息。worker 启动可能处理真实队列，按已确认授权处理。管理员只读 audit、fixture 和真实聊天分别标明。真实模型、文件修改和消息外发需明确各自对象与范围。

公开说明只写通用模板和验证边界；真实用户名、主机/IP、UID、密钥路径、工作目录、聊天来源和会话信息只写仓库外私有记录，或明确被 Git 忽略的 deployments.local/。先核对忽略规则，再写文件；凭据正文不进入任何公开材料。私有记录写清路径映射、启动方式、版本、配对、回滚与未验证事项。核对归属与完整路径后，清理本轮专用测试进程、临时目录及传输文件；保留私有备份。

完成条件：所有适用检查有当前结果，未通过项明确；用户能查状态、选择目录、停止任务并找到恢复材料。最终先报告实际结果，再给文档与待办。进程启动、工具发现或初始化成功，不证明真实模型任务已经可完成。
